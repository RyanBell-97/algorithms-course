Trace vs proof

A trace runs one input and shows it works that once. A proof checks initialization, maintenance, and termination using only the loop's control flow — so it covers all inputs of all sizes at once. Testing can never replace this.

Average vs expected

Average case averages the cost over a distribution of inputs (e.g. all permutations equally likely). Expected case averages over the algorithm's own random choices — as in randomized quicksort, where the pivot is random even for a fixed input. Different source of randomness, same kind of average.

Common pitfalls

  • The worst case is not always rare — for an absent target it is the typical case.
  • An average case is meaningless without stating the input distribution.
  • Big-O is not "the worst case". You can give O, Ω, or Θ for best, worst, or average.

Plane Sweep — why Θ(n log n) beats Θ(n²)

Closest-pair, told as a story about counting. Watch the naive all-pairs count explode while the sweep keeps comparisons local.

The idea

  1. Sort the points by x-coordinate once — Θ(n log n).
  2. Sweep a vertical line left to right.
  3. Keep only points within distance δ of the line — the green active strip.
  4. A new point can only beat δ against points already in the strip.

Why the strip is small

All strip points are already ≥ δ apart, so only a constant number fit in any δ-by-2δ window. Each new point therefore does O(1) work — after an O(log n) lookup. The active set is kept in a balanced BST, which Unit 4 builds in full. This is a taste of asymptotic thinking, not a closest-pair implementation.
